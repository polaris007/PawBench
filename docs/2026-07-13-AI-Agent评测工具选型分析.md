# AI Agent 评测工具/项目选型分析

> 目的：为公司私有化部署的 OpenClaw（及未来其他 AI Agent）选择评测方案。
> 结论：**推荐 PawBench**。

### 2.2 开源情况

所有项目均已开源。但需要注意：

- **PawBench / OpenJudge**：Apache 2.0 / MIT，无商业限制，代码仓库完整。
- **BenchClaw**：以 OpenClaw Skill 形式发布（Skill 代码开源），但**题目从远程服务器拉取**，评分逻辑部分在服务端，不是完全本地可控。
- **WildClawBench**：MIT，代码完整，但**任务素材需联网下载**（YouTube 视频等），离线场景受限。
- **ClawBench (shellbench)**：MIT，代码和任务完全开源，19 个 Core v1 任务。
- **DeepEval / Promptfoo**：框架开源，但**需要自建评测用例和数据集**，不提供现成 Agent 任务。

## 3. 各项目详细分析

### PawBench ★ 推荐

- **维护方**：阿里通义实验室 AgentScope 团队（阿里巴巴集团）
- **定位**：Model × Harness 三维交叉评测（模型、Harness、任务）
- **任务数**：150 道，来自 6 个高质量 Agent 评测子数据集
- **Harness 覆盖**：原生支持 OpenClaw、QwenPaw、Hermes 三种
- **核心优势**：
  1. **最大的现成任务集**（150 题），开箱即用，无需额外开发
  2. **直接支持 OpenClaw**，与公司私有化部署场景完美对齐
  3. **三维交叉评测**：可以独立分析模型因素和 Harness 因素
  4. 阿里通义实验室背书，**国内企业友好**，中英文文档完善
  5. 基于 OpenJudge 框架，未来扩展性强
  6. Docker 沙箱隔离，适合离线内网部署
  7. 切片分析功能（按能力、场景、复杂度、模态、环境五维）定位问题精准
- **与公司场景的匹配**：
  - 公司正使用 OpenClaw → PawBench 原生支持 OpenClaw Harness
  - 公司 LLM 内网部署 → 支持自定义 API 地址（OPENAI_BASE_URL）
  - 未来可能评测其他 Agent → 支持多 Harness 横向对比
  - 国内模型 → 已内置 Qwen、GLM、DeepSeek、Kimi 等

### OpenJudge

- **定位**：AI 评估框架（PawBench 的底层基础设施）
- **功能**：50+ 生产级 Grader（Agent 生命周期、工具调用、多模态、代码、数学等）
- **集成**：与 LangSmith、Langfuse 对接
- **评价**：框架层面非常强大，但直接使用需要更多开发工作。PawBench 是基于 OpenJudge 的上层封装，提供了更便捷的评测入口。**选择 PawBench 天然继承了 OpenJudge 的能力。**

### WildClawBench

- **维护方**：上海 AI Lab (InternLM 团队)
- **任务数**：60 道
- **亮点**：有 arXiv 技术报告，被 ACL 2026 接收为 Best Resource Paper。任务设计真实、难度大（最强制模型仅 ~62%）
- **不足**：
  1. 任务素材需联网（YouTube 视频等），**与内网场景冲突**
  2. Docker 镜像预构建（4 个 Harness 各一个），不易自定义
  3. 部分评分逻辑依赖 OpenRouter，内网场景需要额外适配
- **结论**：学术价值高，但内网离线场景下实用性和可控性不如 PawBench

### ClawBench (shellbench)

- **维护方**：OpenClaw 官方
- **定位**：Trace-based scoring，动态系统诊断
- **任务数**：Core v1 仅 19 题，规模较小
- **亮点**：13 种故障模式分类，SNR 信号分析，配置诊断等研究性功能
- **不足**：
  1. 任务集小（19 题），难以全面覆盖
  2. 与 OpenClaw 版本强绑定
  3. 社区较小（128 Stars），维护力度有限
- **结论**：作为辅助分析工具有价值，但不适合作为主要评测方案

### BenchClaw

- **维护方**：Antutu（安兔兔）
- **形式**：OpenClaw Skill，25 道题
- **亮点**：自动化程度高，一键跑分，有榜单
- **不足**：
  1. **题目从远程拉取**，内网环境不可用
  2. 固定 25 题，不可扩展
  3. 评分部分在服务端，不透明
  4. 仅支持 OpenClaw，不可用于其他 Agent
- **结论**：个人开发者快速跑分有用，企业内网场景不适用

### ClawProBench

- **维护方**：个人开发者 (suyoumo)
- **任务数**：开放数据集 102 题 + 封闭数据集 68 题
- **亮点**：榜单数据丰富，覆盖多模型多维度
- **不足**：个人维护，稳定性不确定；封闭数据集不公开

### PinchBench

- **维护方**：Kilo Code
- **评价**：OpenClaw 早期评测工具，23 类任务，但未针对 OpenClaw 特性深入。更新不频繁，信息较少。

### AgentBench

- **维护方**：OSU 等多校联合
- **评价**：学术性强，场景（OS/DB/WebShop）与"企业个人助理"场景偏离较大。项目已阶段性完结。

### DeepEval / Promptfoo

- **定位**：通用评测框架，**非 Agent 专用**
- **共同不足**：需要自行构建评测数据集和用例，没有现成的 Agent 场景任务
- **场景**：适合已经有自己数据集的团队做持续集成测试，不适合从零开始的 Agent 评测选型

## 5. 结论：选择 PawBench

基于以上多维度分析，建议选择 **PawBench** 作为公司 AI Agent 评测方案，理由如下：

### 核心理由

1. **最大规模的现成 Agent 任务集（150 题）**，覆盖办公、软件工程、安全、信息检索、数据分析等多场景，开箱即用。其他项目最多 60~102 题，DeepEval/Promptfoo 则完全没有现成数据集。

2. **原生适配 OpenClaw**，与公司当前技术栈零摩擦。三个 Harness（OpenClaw、QwenPaw、Hermes）可横向对比，未来若引入其他 Agent 也可在同一评测框架下对比。

3. **国产方案，阿里通义实验室背书**，中文文档完善。国内模型（Qwen、GLM、DeepSeek、Kimi 等）均已内置支持。

4. **企业内网友好**：所有任务离线可运行（无需联网），支持自定义 API 地址，Docker 沙箱隔离，适合内网部署。

5. **基于 OpenJudge 框架**，继承了 50+ 生产级 Grader 和强大的扩展能力，未来自定义评测任务门槛低。

6. **切片分析能力**：按能力、场景、复杂度、模态、环境五个维度分析模型与 Harness 的薄弱环节，指导迭代方向。

### 适用限制

- 需要 Docker 环境
- 并发评测时对服务器磁盘和内存有一定要求（建议 32GB+ 内存、100GB+ 空闲磁盘）
- 需适配内网的 Python 和 Docker 环境（已在《内网离线环境评测操作手册》中详述）
