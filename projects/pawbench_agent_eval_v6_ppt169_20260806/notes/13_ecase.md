# 13 实战评测案例 - 演讲备注

**时长建议**: 90 秒

**讲解要点**:
- 这是我们用 PawBench 做的真实评测：同一 LLM（QWen35-397b）下，OpenClaw 框架从 4.14 升级到 5.28，得分从 68.1 / 66.0 / 70.3（平均 0.6774）降到 60.3 / 61.2 / 59.7（平均 0.6144），平均分下降 6.3 分。
- 关键差异：4.14 错误后能重试恢复 107 次（78.1%），5.28 恢复 0 次。
- 根因一（核心）：错误恢复机制变化。5.28 一旦会话执行过工具（hadPotentialSideEffects 守卫），出错即判定为终态、永久禁止重试；4.14 是简单 error→模型自发重试。官方 issue：#97877（瞬时 HTTP 5xx 被当终态）、#68310（重试仅限 strict-agentic 模型）、#97966 / #100669（2026-07-06 才改为 per-attempt 重试）。
- 根因二（诱因）：LLM 输出提前终止。主因是慢响应/流中断（timeout 2.7–13.1 分钟分散、同一任务时好时坏），maxTokens 截断为辅；5.28 不识别 length、截断的 toolCall 仍被执行、参数变空对象且失败后不恢复。官方 issue：#63210、#97140（v2026.6.10 修复）、#70033。
- 本页预留了「分析附件」区：附 4.14 得分、5.28 得分、得分对比三份 Excel 分析文档。
- 结论：版本升级未必带来收益，PawBench 让「Agent 框架迭代」效果可量化、可归因。

**过渡语**:
这个案例说明，框架升级是好是坏不能凭感觉——最后我们总结一下 PawBench 的核心价值。
